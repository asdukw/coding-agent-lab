# ADR 0002：JSONL Session 与严格恢复语义

- 状态：已采纳
- 日期：2026-07-20

## 背景

Agent 执行是流式、可暂停且可能随时中断的。Session 既要保留逐步事件用于恢复和审计，也要避免一次覆盖中断破坏上一份完整状态。与此同时，恢复逻辑不能把中间损坏或非法状态静默当作正常数据。

## 决策

在 [`src/sessionStore.ts`](../../src/sessionStore.ts) 中采用以下规则：

1. 使用 JSONL 事件记录元数据、消息、工具调用、状态快照和 Memory Extraction 结果。
2. 同一进程内，同一 Session 的保存、追加和索引更新通过串行队列协调。
3. 完整快照先写入目标同目录的临时文件，再原子替换目标，保留上一份完整 Session 直到新文件写完。
4. 恢复时只容忍文件最后一条未写完整的 JSON；中间 JSON 损坏必须失败。
5. 对事件版本、字段、顺序和状态语义进行严格校验，非法内容不能通过类型断言扩大权限或恢复出不一致状态。

## 备选方案

- **每轮直接覆盖单一 JSON 文件**：读取简单，但中断更容易同时破坏历史与最新状态。
- **忽略所有无法解析的行**：可用性较高，却会掩盖中间篡改和事件丢失。
- **立即引入数据库**：可提供事务和跨进程协调，但对当前单进程学习项目增加了不必要的部署与迁移复杂度。

## 后果

- 优点：事件可读、易审计；尾部写入中断可恢复；完整覆盖不会先破坏旧 Session。
- 代价：恢复器必须维护事件顺序和跨字段不变量；格式演进需要显式版本兼容。
- 限制：串行化仅覆盖当前 Bun 进程，不提供多进程并发写入保证。
