# Coding Agent Lab v0.2.0

这个版本重点增强故障可见性、Memory 并发安全、终端交互体验与 Windows Shell 兼容性，并加入可在不修改 workspace 的前提下审计 Memory 健康状态的诊断入口。

## 主要变化

- 危险操作审批改为 Codex 风格的选择菜单，清晰区分单次允许、Session 级允许与拒绝。
- Shell 和其他工具的执行失败采用结构化分类，并持久化到 Session 与工具执行记忆；恢复后的 Agent 能区分命令失败、执行基础设施失败与取消。
- Memory 写入改为带完整性校验的跨进程事务锁和原子替换，覆盖锁损坏、所有者失效、超时与并发写入场景。
- 新增严格只读的 `--memory-check`：报告无效 frontmatter、不可读或过大的 topic、精确重复、过期内容，以及索引缺失、错位或漂移，不创建或修复任何文件。
- TUI 将输入状态与高频流式输出解耦，改善长响应期间的输入延迟和重渲染开销。
- Windows Sandbox 协议升级到 v3；优先使用受信任的 PowerShell 7，在不可用时显式回退到系统 Windows PowerShell 5.1，并在 Shell 结果中报告 engine、兼容版本与 fallback 状态。
- Shell 只在命令启动前选择引擎；命令开始执行后不会换壳重试，避免重复产生副作用。

## 升级注意事项

v0.2.0 的 `cagent.exe` 与 `cagent-windows-sandbox-runner.exe` 使用协议 v3，必须成套升级。不要把本版本 CLI 与 v0.1.1 的协议 v2 runner 混用。

下载 `coding-agent-lab-v0.2.0-windows-x64.zip` 及同名 `.sha256`，校验后解压到目标 workspace 之外的稳定目录，并保持以下两个文件位于同一目录：

- `cagent.exe`
- `cagent-windows-sandbox-runner.exe`

发行包不再强制另行安装 PowerShell 7；标准 Windows 11 可使用内置 Windows PowerShell 5.1。真实 DeepSeek 模型仍需通过父进程环境变量提供 `DEEPSEEK_API_KEY`，发行 EXE 不加载 workspace `.env`。

## 已知边界

- 仅发布 Windows x64 发行物；Ubuntu 仅用于 TypeScript 控制面、离线测试与 Demo 验证。
- 二进制未做代码签名，Windows 可能显示 SmartScreen 提示。
- Windows 原生 Sandbox 只约束内置 Shell 的文件写入和进程生命周期，不隔离网络，也不是宿主机保密边界。
- Full Access 是显式危险模式，会继承当前宿主用户的文件、环境变量与网络权限。
- 回退到 Windows PowerShell 5.1 时，命令必须使用 5.1 兼容语法；Shell 首次执行结果会显式报告实际引擎。

完整安全假设与残余风险见仓库中的 `README.md` 和 `native/windows-sandbox-runner/README.md`。
